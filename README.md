# ОРИП — лабораторные работы 1–4

Учебный проект по дисциплине «Основы развертывания интеллектуальных приложений». На одном примере прошли путь от обучения модели до API, контейнера, автоматической сборки и мониторинга.

Используем датасет Wine из scikit-learn: 178 образцов, 13 числовых признаков и 3 категории вина. Модель — Random Forest. Работы выполнялись в Windows, VS Code и PowerShell, с Python 3.14. Для Docker используется Docker Desktop с WSL2.

## Лабораторная 1. Данные и эксперименты

- Создали виртуальное окружение, настроили Git и DVC.
- Подготовили две версии данных: 163 и 178 строк.
- Проверили переключение версий и восстановление данных из отдельного локального хранилища DVC.
- Обучили три варианта Random Forest, записали параметры, метрики, модели и графики важности признаков в MLflow.
- Зарегистрировали выбранную модель как `wine_production_model`, версия 1, стадия Staging.
- Экспортировали её в ONNX и проверили предсказания через ONNX Runtime.

Разделение данных: 142 объекта для обучения и 36 для проверки, с фиксированным random_state=42 и сохранением пропорций классов.

| Деревьев | Максимальная глубина | Accuracy | F1 macro |
|---:|---:|---:|---:|
| 100 | 5 | 1.0000 | 1.0000 |
| 10 | 2 | 0.9722 | 0.9743 |
| 150 | 15 | 1.0000 | 1.0000 |

Выбрали вариант 100/5: на этой проверочной выборке он получил то же качество, что и более сложный вариант. Эти результаты не означают, что модель всегда отвечает без ошибок.

## Лабораторная 2. API и Docker

- Создали FastAPI-сервис с адресом `POST /v1/predict`.
- Описали 13 входных признаков и структуру ответа через Pydantic.
- Настроили загрузку ONNX-модели один раз при старте процесса сервера через lifespan.
- Проверили правильный запрос (200), отрицательное значение и текст вместо числа (422).
- Написали клиент для пяти последовательных запросов.
- Собрали многоэтапный Docker-образ и проверили запрос из Postman к контейнеру.

Ответ API содержит `predicted_class`, `probabilities` и `model_status`.

## Лабораторная 3. Автоматические проверки и доставка

- Написали три теста pytest: предсказание и две ошибки валидации.
- Настроили GitHub Actions: `lint → test → build_image` после отправки коммита в main.
- Подключили Docker Hub через секреты GitHub и публикацию образов с тегом полного хэша коммита.
- Запустили опубликованный образ через Docker Compose.
- Проверили обновление метки сервиса с `wine_onnx_v1.0` на `wine_onnx_v1.1_updated` и откат к старому образу.

Сборка и публикация выполняются автоматически. Развертывание и откат проверяли вручную командами Compose. При замене одного контейнера возможен короткий перерыв в доступности.

Образы: [tranquillasunset/wine_api_service](https://hub.docker.com/r/tranquillasunset/wine_api_service).

## Лабораторная 4. Мониторинг и дрейф данных

- Добавили `/metrics`: счетчик успешных предсказаний по классам и версии, гистограмму времени подготовки данных и инференса.
- Запустили API, Prometheus и Grafana через Compose.
- Создали дашборд: успешные предсказания в секунду, задержки p50/p95/p99 и распределение классов за последние 5 минут.
- Проверили нагрузку Locust с 10 пользователями: сначала один исходный образец, затем смесь примерно 10% исходных и 90% искусственно смещенных запросов.
- Наблюдали смену преобладающего класса с 0 на 2 при отсутствии ошибок запросов.
- С помощью Evidently сравнили исходный Wine и отдельную искусственную выборку из 1000 строк. Тест Колмогорова — Смирнова при пороге p-value 0.05 обнаружил дрейф у 13 из 13 признаков. Сработал консольный алерт, создан HTML-отчет.

Текущая выборка для Evidently — симуляция, а не выгрузка запросов Locust. Дрейф указывает на изменение данных, но сам по себе не доказывает снижение точности модели.

## Как запустить

Все команды ниже выполняются из папки проекта в PowerShell. Сервисы используют текущую версию кода ЛР4; предыдущие состояния сохранены в истории Git.

### API и мониторинг

Запустить Docker Desktop, затем:

```powershell
docker compose up -d --build
docker compose ps
```

| Сервис | Адрес |
|---|---|
| Swagger UI — отправка запросов | http://127.0.0.1:8000/docs |
| Метрики API | http://127.0.0.1:8000/metrics |
| Prometheus | http://127.0.0.1:9090 |
| Grafana | http://127.0.0.1:3000 |

В новой Grafana стандартный первый вход — admin/admin, затем пароль меняется. Добавить источник Prometheus с адресом `http://prometheus:9090` и импортировать `grafana_dashboard.json`, выбрав источник данных при импорте.

Остановка:

```powershell
docker compose down
```

Тома сохраняют настройки Grafana и историю Prometheus. Экспорт дашборда содержит настройки панелей, но не историю измерений. Образы мониторинга сейчас используют тег latest, поэтому при повторном скачивании их версии могут отличаться.

### Локальные тесты и нагрузка

Если окружение еще не создано:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements-api.txt
.\venv\Scripts\python.exe -m pip install pytest httpx requests locust==2.47.0
```

Тесты не требуют запущенного сервера:

```powershell
.\venv\Scripts\python.exe -m pytest test_main.py -v
```

Для клиента и Locust API должен работать:

```powershell
.\venv\Scripts\python.exe client_test.py
.\venv\Scripts\python.exe -m locust -f locustfile.py --host http://127.0.0.1:8000
```

Locust открывается по адресу http://localhost:8089. Использовали 10 пользователей и запуск 2 пользователей в секунду. Текущий файл содержит смесь задач с весами 1 и 9. Для повторения только обычной нагрузки временно отключите смещенную задачу, например заменив у нее `@task(9)` на `@task(0)`, и перезапустите Locust. После проверки верните вес 9. Нагрузку останавливают кнопкой Stop, процесс Locust — Ctrl+C в терминале.

### Анализ дрейфа

Для Evidently используется отдельное окружение: версия 0.7.23 не импортировалась с pandas 3.1.1, поэтому здесь зафиксирована pandas 2.3.3.

```powershell
python -m venv venv-drift
.\venv-drift\Scripts\python.exe -m pip install -r requirements-drift.txt
```

Скрипту нужен `data/dataset.csv` версии 2. Если CSV отсутствует, его можно восстановить в окружении с scikit-learn и pandas:

```powershell
.\venv\Scripts\python.exe -m pip install scikit-learn pandas
.\venv\Scripts\python.exe prepare_data.py --version 2
.\venv-drift\Scripts\python.exe drift_detector.py
Start-Process .\data_drift_report.html
```

Если CSV уже есть, достаточно двух последних команд. Сервер и контейнеры для анализа не нужны.

### Повторение обучения из ЛР1

Для обучения нужны зависимости из `requirements.txt`. В отдельном терминале запустить MLflow:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe prepare_data.py --version 2
.\venv\Scripts\python.exe -m mlflow server --backend-store-uri sqlite:///mlflow.db --serve-artifacts --artifacts-destination ./mlflow_artifacts --host 127.0.0.1 --port 5000
```

Интерфейс MLflow: http://127.0.0.1:5000. Во втором терминале запустить `train.py`. Для трех вариантов менять в нем пары `n_estimators, max_depth`: `(100, 5)`, `(10, 2)`, `(150, 15)`. Текущий файл содержит `(150, 15)`.

Перед запуском `export_onnx.py` зарегистрировать выбранный запуск 100/5 под именем `wine_production_model`, версия 1. В первой работе модель также переводилась в Staging. Готовый ONNX-файл уже включен в Git, поэтому для API и тестов повторять обучение не требуется.

## Что хранится отдельно

CSV отслеживается DVC, а его указатель — Git. Хранилище DVC в этой работе — локальная папка рядом с проектом; на другом компьютере она автоматически не появится. Данные можно заново создать через `prepare_data.py`.

Окружения Python, база и артефакты MLflow, кэши и сгенерированный HTML-отчет не публикуются в Git. Журнал MLflow после клонирования нужно создавать заново. ONNX-модель, исходный код и конфигурации находятся в репозитории. Для публикации образов в своем репозитории нужны секреты GitHub `DOCKERHUB_USERNAME` и `DOCKERHUB_TOKEN`; сами значения в код не записываются.
