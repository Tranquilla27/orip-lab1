# ОРИП — лабораторная работа №1

Трекинг экспериментов и версионирование артефактов на примере классификации Wine.

## Данные и результаты

Wine: 178 объектов, 13 признаков, 3 класса. Версия данных 1.0 содержит 163 объекта, версия 2.0 — 178. Разделение: 142 объекта для обучения, 36 для проверки; random_state=42, стратификация по классу.

| Число деревьев | Максимальная глубина | Accuracy | F1 macro |
|---:|---:|---:|---:|
| 100 | 5 | 1.0000 | 1.0000 |
| 10 | 2 | 0.9722 | 0.9743 |
| 150 | 15 | 1.0000 | 1.0000 |

Для регистрации выбрана модель со 100 деревьями и глубиной 5. Результаты относятся к одному фиксированному разбиению выборки.

## Файлы

- `prepare_data.py` — создание двух версий данных.
- `train.py` — обучение Random Forest, запись параметров, метрик, модели и графика в MLflow.
- `export_onnx.py` — экспорт версии 1 зарегистрированной модели в ONNX.
- `inference_onnx.py` — запуск ONNX Runtime без импортов MLflow и scikit-learn.
- `data/dataset.csv.dvc` — указатель DVC на данные.
- `requirements.txt` — зафиксированные зависимости. Работа выполнена на Python 3.14 под Windows.

## Запуск в Windows PowerShell

Выполняйте команды из корня репозитория.

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe prepare_data.py --version 2
```

CSV не хранится в Git: скрипт создаёт его из встроенного набора scikit-learn. Настроенный DVC remote — локальная папка `../../dvc_remote_storage` относительно `.dvc/config` (соседняя с папкой проекта). Её содержимое на GitHub не публикуется. На другом компьютере `dvc pull` не восстановит данные без доступа к исходному хранилищу; используйте скрипт подготовки или настройте собственное хранилище.

Запустите MLflow и оставьте терминал открытым:

```powershell
.\venv\Scripts\python.exe -m mlflow server --backend-store-uri sqlite:///mlflow.db --serve-artifacts --artifacts-destination ./mlflow_artifacts --host 127.0.0.1 --port 5000
```

Интерфейс: http://127.0.0.1:5000. Во втором терминале:

```powershell
.\venv\Scripts\python.exe train.py
```

Для повторения трёх экспериментов задавайте в `train.py` пары `n_estimators, max_depth`: `(100, 5)`, `(10, 2)`, `(150, 15)`, сохраняя файл перед каждым запуском. Текущий код содержит `(150, 15)`.

В MLflow откройте модель запуска `forest_100_depth_5`, зарегистрируйте её под именем `wine_production_model` и переведите версию 1 в Staging. При необходимости выключите New model registry UI для доступа к стадиям. Экспорт использует конкретную версию 1; убедитесь, что зарегистрирован нужный запуск.

```powershell
.\venv\Scripts\python.exe export_onnx.py
.\venv\Scripts\python.exe inference_onnx.py
```

Проверка инференса использует по одному образцу каждого класса. Это проверка работоспособности экспортированной модели, а не независимая оценка качества и не полное сравнение выходов scikit-learn и ONNX.

Окружение, база и артефакты MLflow, кэш DVC и сгенерированный ONNX-файл исключены из Git. После клонирования журнал экспериментов и реестр создаются заново описанными шагами.
